# Inclusion Criteria for New Recipes

Conan Center is a curated repository for open-source libraries that can be built from C and C++ sources. To ensure long-term maintainability, we accept recipes for projects that meet three core criteria:

1. **Not in early development:** Stable enough that breaking changes are infrequent and users can update without major disruption.
2. **In use or very likely to be used:** Adopted by developers, teams, or projects beyond the original author.
3. **Actively maintained:** Supported by an upstream that provides ongoing care and responds to its community.

## How We Evaluate New Recipe Proposals

Conan Center maintainers will assess the suitability of a recipe for inclusion in the repository based on the signals below. No single item is a strict pass/fail gate; strength in some areas can balance weakness in others:

- **Development track record:** A verifiable public development history over a sustained period of time.
- **Adoption beyond the author:** External engagement such as dependent projects, inclusion in other package managers or repositories, or evidence of feedback from users in the form of issues, pull requests, forks, or stars.
- **Signs of ongoing care:** Commits or releases spread over time and an upstream issue tracker that receives responses.
- **Clear purpose and documentation:** A README or equivalent that clearly explains what the library does and provides basic usage instructions.
- **Unequivocal name:** A project name that has stayed the same, is easy to find, and doesn't clash with existing packages.
- **Explicit open-source license:** A clearly stated open-source license or equivalent.

## Signals a Project May Not Be Ready Yet

Several of these factors appearing together suggest that a library needs more time to mature before being added. None of them is necessarily a blocker on its own:

- **Negligible public history:** The source repository is only a few weeks old.
- **Unreviewed code:** Large amounts of code added in a short period without external review, including code generated by AI tools with no evidence that a human has reviewed it.
- **Unestablished release cycle:** Bursts of many releases in a short amount of time, or no evidence of a release policy.
- **No external engagement:** Activity, issues, and commits come exclusively from the author, with no outside users or dependents yet.
- **Lack of documentation:** No README or equivalent explaining what the library does and how to use it.
- **Lack of modern practices:** No CI validation, or no evidence of it, such as automated builds and tests across platforms.
- **High volatility:** The project name, versioning scheme, or public APIs are still changing rapidly.
- **Abandonment or dormancy:** The repository is archived, declared inactive, or maintainers have been unreachable for extended periods.

---

If a proposal does not fit these guidelines, please open an issue instead. Exceptions will be considered on a case by case basis.
